# Programme repair and reviews

Load only to repair missing/malformed state or conduct a weekly/monthly review. The programme files are `MISSION`, `ROADMAP`, `NOW`, `EVIDENCE`, and `PARKING-LOT`.

## Repair

Derive state only from observable workspace sources: existing programme/topic records, accepted project artifacts, repository history, and explicit learner statements. Ask one necessary question and stop when mission intent or constraints cannot be recovered. Never invent evidence, demonstrated understanding, gates, or progress. Bootstrap absent files conservatively, preserve recoverable IDs/history, and validate all five files against the runtime schema in `SKILL.md` before any lesson.

When reconstructing `EVIDENCE.md`, preserve this exact table schema even when it has no rows:

```markdown
| Date | CAP ID | Criterion | Status | Evidence class | Problem | Demonstration | Artifact or result | Assessor |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
```

Status is `candidate|accepted`; accepted entries are reviewed promotions of existing eligible candidates. Never infer a row merely because an artifact exists.

## Weekly review

Do not run a lesson. Reconcile the attempted exercise, pending state, blockers, gates, evidence, topic records, and production reality. Update `NOW` to one spine, question, and action; mutate `PARKING-LOT` if needed, promoting an item only as a time-boxed unblocker or replacement after explicit demotion. Complete only when the current phase/capability and all affected files are consistent.

## Monthly review

Do not run a lesson. Review production capabilities, public artifacts, interviews, and leadership; reconcile candidate/accepted evidence and gates, phase/capability, and roadmap/parking changes. Reorder only for a production opportunity, demonstrated recurring weakness, or changed career goal; preserve IDs and record why. Update the `NOW` date and exactly one next action. Complete only when all five files agree.
